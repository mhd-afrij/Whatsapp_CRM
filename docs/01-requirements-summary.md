# 01 — Requirements Summary

## 1. Product Overview

A single-tenant-per-deployment WhatsApp CRM & Team Collaboration Platform. Each deployment
("workspace") links exactly **one** WhatsApp number and gives a team shared, role-controlled
access to a unified inbox, contact/lead/deal management, tasks, notes, and reporting.

Three cooperating services:

| Service            | Stack                                                                                              | Responsibility |
|---------------------|------------------------------------------------------------------------------------------------------|----------------|
| `frontend`          | Next.js 14+ (App Router), TypeScript strict, Tailwind, shadcn/ui, TanStack Query, RHF + Zod, Socket.IO client, Recharts | All user-facing UI, realtime inbox, dashboards |
| `backend`           | Laravel 12, PHP 8.3+, MySQL 8, Redis                                                                 | REST API (`/api/v1`), auth/RBAC, CRM business logic, queues, notifications |
| `whatsapp-gateway`  | Node 20+, TypeScript, Express, Baileys, Redis, BullMQ, Socket.IO, MySQL, Zod, Pino                   | WhatsApp protocol connection, message send/receive, session lifecycle, realtime fan-out |

## 2. Functional Requirements

### 2.1 Authentication & Authorization
- Email/password login, session-based auth (Laravel Sanctum), logout, password reset.
- 5 roles: Super Admin, Admin, Manager, Agent, Viewer.
- **Permission-based** authorization (Laravel Gates/Policies backed by a `permissions` table), not
  hard-coded role name checks — roles are just named bundles of permissions and are editable by
  a Super Admin/Admin from Role Admin UI.
- Invitations: admin invites a user by email, user accepts and sets a password.

### 2.2 Shared Team Inbox
- 3-panel layout: conversation list (left) — active chat (center) — contact/deal context (right).
- Realtime message delivery via Socket.IO (server pushes; gateway is source of WhatsApp events).
- Conversation assignment to a user or team; unassigned queue.
- Conversation status: open, pending, closed, reopened.
- Typing indicators, read receipts, delivery/failure status per message.
- Internal notes on a conversation (not sent to WhatsApp) with @mentions.
- Media messages (image, video, audio, document, sticker) with thumbnails and download.
- Message reactions (emoji) mirrored from WhatsApp.
- Search within a conversation and global search across conversations/contacts/leads/deals.

### 2.3 Contacts
- Auto-created from inbound WhatsApp messages (gateway-owned `whatsapp_contacts`), enriched by
  CRM fields (name, email, company, tags, custom fields) owned by Laravel (`contacts`).
- Merge/link a `whatsapp_contacts` row to a CRM `contacts` row.
- Activity timeline per contact (messages, notes, deals, tasks).

### 2.4 Leads / Deals / Pipelines
- Kanban pipelines with configurable stages per workspace.
- Convert a conversation/contact into a Lead, then into a Deal attached to a pipeline stage.
- Deal stage history audit trail, deal value, expected close date, owner.
- Multiple pipelines per workspace (e.g. Sales, Support Escalation).

### 2.5 Tasks & Calendar
- Tasks with due date, assignee, priority, status, linked to a contact/lead/deal/conversation.
- Task comments and reminders (in-app + notification).
- Calendar view aggregating tasks.

### 2.6 Labels
- Workspace-defined labels, color-coded, applicable to contacts, conversations, leads, deals
  (polymorphic-style via explicit pivot tables).

### 2.7 Notifications
- In-app notification center + realtime push via Socket.IO.
- Notification preferences per user per event type (email/in-app toggle).
- Events: new assigned conversation, mention in note, task due, deal stage change, WhatsApp
  disconnect, etc.

### 2.8 Global Search
- Cross-entity search (contacts, conversations, messages, leads, deals) with saved filters.

### 2.9 Dashboard / Analytics
- Recharts-driven dashboard: conversation volume, response time, agent workload, pipeline
  conversion, task completion.

### 2.10 Admin
- User management (invite, deactivate, reassign role).
- Team management (create teams, assign members, team-scoped conversation routing).
- Role/permission management (create custom roles from permission list).
- Workspace settings (business hours, branding, default pipeline, notification defaults).
- Audit log viewer (who did what, when).

### 2.11 WhatsApp Connection Management
- QR-code linking flow surfaced in the frontend, generated by the gateway.
- Connection status (connected / connecting / disconnected / logged_out) visible to admins.
- Reconnect on transient failure, with backoff; manual "relink" when session invalidated.
- Session persisted (multi-device credentials) across gateway restarts.

## 3. Non-Functional Requirements

- **Multi-service consistency**: single MySQL database shared by backend and gateway under an
  explicit table-ownership boundary (see `DATA_OWNERSHIP.md`).
- **Realtime**: message/event propagation gateway → DB → Socket.IO → frontend must be low
  latency (target < 1s under normal load).
- **Reliability**: outbound WhatsApp sends go through a durable BullMQ queue with retry/backoff;
  failures are recorded (`message_processing_failures`) and surfaced to the UI.
- **Idempotency**: WhatsApp messages deduplicated via `UNIQUE(workspace_id, whatsapp_message_id)`.
- **Security**: RBAC enforced server-side on every endpoint (policies/gates + middleware), audit
  logging of sensitive actions, internal service-to-service calls authenticated with a shared
  secret, secrets never in the repo, `.env`-driven config, Zod-validated env for the gateway.
- **Scalability**: stateless Laravel + Node processes behind Nginx; Redis for cache/session/queue
  broker; MinIO (S3-compatible) for media storage so app servers stay stateless.
- **Observability**: structured logging (Pino for gateway, Laravel log channels for backend),
  health-check endpoints on all services, queue/job failure visibility (`failed_jobs`).
- **Deployability**: Docker Compose for dev and prod, Nginx reverse proxy/TLS termination,
  zero-downtime deploy strategy for the backend (see `10-deployment-plan.md`).
- **Data integrity**: soft deletes on business-critical tables, foreign keys enforced at the DB
  level, migrations are the single source of truth for schema.
- **Accessibility & design consistency**: shadcn/ui + Tailwind design tokens (see color palette
  below) applied consistently across the frontend.

## 5. Out of Scope (this deployment model)

- Multi-workspace-per-tenant switching in one deployment (each deployment = one workspace).
- Multiple linked WhatsApp numbers per workspace.
- Outbound channels other than WhatsApp (no SMS/email channel unification in v1).
