# User, Role, Permissions Access List## OverviewThis CRM-Whatsapp system uses a **permission-based authorization model** (not role-name checking).- **Authorization checks in code always test a permission string** (e.g., `$user->can('contacts.edit')`), never a role name.- Roles are just named bundles of permissions and are editable by a Super Admin/Admin from Role Admin UI.- Permissions are additive and stored in the `permissions` table, granted to `roles` via `permission_role` pivot table.---## Database Schema### Users Table| Column | Type | Description ||--------|------|-------------|| id | bigint | Primary key || workspace_id | bigint | Foreign key to workspaces || name | string | User display name || email | string | User email || username | string | User username || password | string | Hashed password || avatar_path | string | Avatar image path || about | text | User bio || position | string | Job position || is_active | boolean | Account active status || last_login_at | datetime | Last login timestamp |### Roles Table| Column | Type | Description ||--------|------|-------------|| id | bigint | Primary key || workspace_id | bigint | Foreign key to workspaces || name | string | Role display name |---## System Roles (5 Default Roles + Owner)| Role | Slug | Description ||------|------|-------------|| **Super Administrator** | `super-administrator` | Full unrestricted access, including role/permission management and irreversible actions. || **Owner** | `owner` | Account owner with full control of the workspace. (`App\Models\User`)- `hasPermission(string $permission): bool`- `hasAnyPermission(array $permissions): bool`- `permissionNames(): Collection` (cached per request)- `isSuperAdmin(): bool`- `isWorkspaceOwner(): bool`- `isAdmin(): bool`- `roleKeys(): array` ['super_admin'|'admin'|'user']- `hasRoleKey(string $roleKey): bool`### Role Model (`App\Models\Role`)- `users`: BelongsToMany relationship- `permissions`: BelongsToMany relationship### Permission Model (`App\Models\Permission`)- `roles`: BelongsToMany relationship---## Authorization Enforcement1. **Route Middleware**: `permission:{name}` on `/api/v1` routes2. **Policies**: Record-level Own/Team scoping3. **Frontend**: UI hides/disables based on permissions (UX only)4. **Audit Log**: Records permission-gated mutations---## Key Files| File | Purpose ||------|---------|| `backend/app/Models/User.php` | User model with permission methods || `backend/app/Models/Role.php` | Role model || `backend/app/Models/Permission.php` | Permission model || `backend/database/seeders/PermissionSeeder.php` | Seeds 41 permissions || `backend/database/seeders/RolePermissionSeeder.php` | Seeds 5 system roles with permissions || `docs/07-permission-matrix.md` | Permission matrix documentation---## Important Notes1. **Super Admin bypass**: Super Admins bypass permission checks in some routes2. **Owner vs Super Admin**: Workspace Owner has full workspace control but NOT platform privileges (isSuperAdmin() is false for Owners)3. **Permission caching**: Permissions are cached per-request on User model4. **Additive permissions**: Users can have multiple roles (union of all permissions)5. **Record-level scoping**: Own/Team scoping enforced by Policies, not separate permission strings## Role
